# audit-service migrations

Applied by the explicit migration step (`npm run migrate`, as `audit_migrator`) after the service-kit baseline
(`libs/service-kit/migrations`), never at startup; the readiness check (`migrations`) fails while any file here is unapplied. Forward
only: a change is a new numbered file. Only `*.sql` files count; this README is ignored by the runner.

| File | Stage | Adds |
|---|---|---|
| `0001_audit_record.sql` | 18.3 | the append-only `audit_record`: shapes, the actor / subject / changes invariants, the database clock, the unique (sourceService, eventId), the V1 indexes, append-only triggers, and `audit_restrict_to_append_only` ([record](../../../../docs/architecture/stage-18/stage-18-3-persistence-append-only.md)) |
| `0002_audit_record_time_idx.sql` | 18.6 | the platform-wide time index `("occurredAt" DESC, id DESC)`: an all-organizations platform read otherwise scanned the whole table (measured: 32–42 ms → 0.08–0.19 ms at 500 000 rows; [record](../../../../docs/architecture/stage-18/stage-18-6-query-authorization.md)) |
| `0003_retention.sql` | 18.8 | the retention path (ADR-0049 A41): `audit_retention_policy` (owner-only, ships EMPTY = never purge), the append-only `audit_retention_run` ledger, the trigger admitting a DELETE only past a category's horizon (`recordedAt`), `audit_grant_retention(role)` (DELETE + SELECT of id / category / recordedAt; refuses the runtime), and the purge index `(category, recordedAt, id)` ([record](../../../../docs/architecture/stage-18/stage-18-8-security-privacy-retention.md)) |
| `0004_changes_validation_search_path.sql` | V2 A13.3a | `audit_changes_valid` gets a fixed `search_path = public, pg_temp`, so the `changes` CHECK resolves its inner call when `pg_restore` loads data with an empty search_path: a backup of a non-empty audit database restores (found by the A13 restore drill; 0001 unchanged) |
| `0005_event_provenance.sql` | Core V2 S1b-2 | the append-only `event_provenance` and `event_provenance_conflict` (ADR-0057 §13.2 with its Audit admission clarification, S0-C1; observe-only): the provenance of every ADMITTED `audit.*` delivery, committed before ingestion; nothing for a delivery refused at admission. Append-only for every role (triggers, `audit_restrict_to_append_only`; the retention grant does not cover them). No purge: P-A2 open, production gate AP-R (not enforced here). In production it stacks after 0004 (M9) and changes the G-7 fingerprint |
| `0006_audit_contract_v2.sql` | Core V2 S2-Audit.1 | ADR-0069 decisions 2 and 4, expand only: nullable `audit_record` columns `companyId`, `platformId`, `liveMode` (version-2 facts as asserted; a CHECK keeps them NULL on version-1 records) and `producerIdentityVerified`, `replayed` (the delivery's trust decision; NULL for history and for Audit's own records), a CHECK that one id never names two scope levels, and the insert-only `audit_record_scope` (trusted scope rows, basis `verified_producer` only): its trigger admits a row only for a producer-verified record inserted by the same transaction, with exactly that record's assertion; UPDATE, DELETE and TRUNCATE are refused for every role. No foreign key: the retention path is unchanged. No existing row changes; in production it stacks after 0005 (G-7 fingerprint) |
| `0007_audit_approved_by.sql` | Core V2 S2-Audit.2 | ADR-0069 decision 3 (Owner decision D5), expand only: nullable `audit_record` columns `approvedByUserId`, `approvedByUserKind` (the verified approver as the recording service verified it; today only `authorization_receipt.consumed`), with a CHECK: both or neither, version 2 only, a known user kind. No existing row changes |

**Convention for every later append-only table:** default privileges give the runtime role UPDATE / DELETE on each new table; the
migration that creates one must call `SELECT audit_restrict_to_append_only('<table>');` and add the append-only triggers.
