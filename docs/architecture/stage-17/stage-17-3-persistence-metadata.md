# Stage 17.3 — File persistence and metadata

- **Status:** merged (PR #107); certified with the whole of Stage 17 in [17.10](./stage-17-10-focused-certification.md).
- **Scope:** the durable `file` and `file_access_ticket` model (`apps/file-service/db/migrations/0001_file_schema.sql`) and its
  repository layer (`apps/file-service/src/persistence/`): metadata, ownership, organization scope, storage identity, integrity fields,
  the lifecycle, ticket persistence (digest, bindings, expiry, use, revocation).
- **Still impossible after 17.3:** storing, uploading, downloading or reading bytes; issuing or redeeming a usable ticket; physical
  deletion; scanning. No route besides `/health` and `/ready`; no storage adapter, SDK or byte stream exists.
- **Frozen design followed:** [ADR-0048](../../adr/0048-file-service-architecture.md), [SDD §3, §5, §6, §10, §11.1](../../sdd/file-service.md),
  [Stage 17.1](./stage-17-1-decisions-and-roadmap.md) (F2, F3, F4, F10, F11, F16, F17, F30, F33, F35, F36). No decision was reopened.

## 1. Baseline and conformance

`main` at `fb21f47` (Stage 17.2 merged, PR #106). The prompt and the frozen documents agree. One inconsistency **inside** Stage 17.1
was found and corrected: its threat-model row said the ticket token is "stored as HMAC", while F35 and SDD §11.1 (the decisions) say
a SHA-256 digest with no key. The row now matches F35. The SDD §3 table was clarified where the implementation had to choose (§10).

## 2. Schema

```text
┌──────────────────────────────────────────────┐
│ file                          (never deleted) │
├──────────────────────────────────────────────┤
│ id                uuid PK   (server, v4)      │ immutable
│ ownerService      text      (caller grammar)  │ immutable ── the authenticated caller
│ organizationId    uuid NULL (NULL = platform) │ immutable
│ createdBy         text NULL (opaque, ≤128)    │ immutable
│ originalName      text NULL (NFC, ≤255 B, …)  │ immutable ── presentation only
│ declaredMediaType text NULL (hint)            │ immutable
│ mediaType         text NULL (allow-list)      │ set once ─┐ required from VERIFYING on
│ sizeBytes         bigint NULL (0..100 MiB)    │ set once  │ (the content is complete)
│ sha256            text NULL (64 lower hex)    │ set once ─┘
│ storageProvider   text                        │ immutable
│ storageKey        text UNIQUE                 │ immutable ── <prefix>/<id>/<32 hex>
│ status            text (7 states, §3)         │ state machine
│ uploadExpiresAt   timestamptz (lease)         │ immutable
│ attachDeadline    timestamptz NULL            │ immutable ─┐ attached OR a deadline
│ attachedAt        timestamptz NULL            │ set once  ─┘
│ idempotencyKey / requestHash  (pair) NULL     │ immutable
│ failureCode       text NULL                   │ set once ── iff REJECTED / FAILED
│ createdAt, availableAt, deletionRequestedAt,  │ set once, ordered, agree with status
│ deletedAt, updatedAt (trigger)                │
└───────────────────────┬──────────────────────┘
                        │ file_access_ticket_file_fk (NO ACTION; no cascade)
                        │ + binding trigger: the file's owner = issuedBy, its organization = organizationId
                        ▼
┌──────────────────────────────────────────────┐
│ file_access_ticket          (rows may expire) │
├──────────────────────────────────────────────┤
│ id                uuid PK                     │ immutable
│ operation         'download' | 'upload'       │ immutable
│ fileId            uuid NULL                   │ download: at insert · upload: set once (the created file)
│ issuedBy          text (caller grammar)       │ immutable ── the owner that issued it
│ organizationId    uuid NULL                   │ immutable
│ tokenDigest       text UNIQUE (64 lower hex)  │ immutable ── SHA-256(token); never the token
│ disposition       'attachment' | 'inline'     │ immutable ── download only
│ maxBytes, mediaTypes[], attach                │ immutable ── upload intent only
│ singleUse         boolean (upload: true)      │ immutable
│ useCount / usedAt (first use)                 │ +1 at a time, only while valid
│ revokedAt         timestamptz NULL            │ set once
│ expiresAt         createdAt + 60..300 s       │ immutable ── never extended
│ createdAt                                     │ immutable
└──────────────────────────────────────────────┘
```

Conventions follow Notification / Billing / Payment: quoted camelCase columns, `timestamptz` from the database clock (`now()`, UTC
regardless of the host time zone), a CHECK on every enumeration, triggers only for what a CHECK cannot express, trigger messages with
ids and states only. No `bytea`, large object, JSON metadata column or product concept exists (a test reads the catalog).

## 3. File model

- **Identifier (F30):** UUID v4 generated by the application (`randomUUID`) before the insert, because the storage key embeds it. It
  identifies a file, it never authorizes: every read requires the owner and the organization (§6).
- **Ownership (F2):** `ownerService` is written from `FileScope.ownerService`, which the API stages fill from the authenticated caller
  (a ticket upload: the ticket's `issuedBy`). No input field can set it; a test smuggles `ownerService`, `id`, `storageKey` and `status`
  into the input and gets the derived values.
- **Organization scope:** `organizationId` is optional (NULL = platform file, allowed by ADR-0048 §2) and immutable. File Service never
  verifies it against Auth or Organization; the caller policy (`none` / `request`) bounds it at the API (17.5).
- **Storage identity (SDD §6):** `newStorageKey(prefix, fileId)` = `<prefix>/<fileId>/<16 random bytes, hex>`, from server values
  only (the configured prefix, 17.4, and the generated id), in the adapter grammar `^[a-z0-9/-]{1,200}$`. The schema re-checks that
  the key has that shape **and contains the row's own id**; it is unique and immutable. No filename, type or organization is in it.
- **Metadata (F3):** `originalName` is presentation metadata; the schema refuses control characters (C0 / C1), bidi overrides and
  isolates, path separators, non-NFC text, more than 255 UTF-8 bytes and `.` / `..` (the sanitizer that produces it is 17.5; the
  constraint is the last line of defence). `mediaType` is the **verified** type (V1 allow-list in a CHECK: extending F13 is a
  migration, on purpose); `declaredMediaType` is a bounded hint only. Neither is ever trusted from a client in 17.3: nothing sets them
  except the future upload.
- **Integrity:** `sha256` lowercase hex (the Core digest representation: kit tokens, Notification checksums; also the future ETag).
  **No UNIQUE on it** (F33, no deduplication; tested with two files, two owners, one checksum).
- **Size:** `bigint`, `0..104857600` (the frozen F29 ceiling). The per-caller and per-ticket limits are enforced on the stream (17.5).

## 4. Lifecycle (SDD §5)

| From → to | Allowed | Notes |
|---|---|---|
| (insert) → `UPLOADING` | only | a trigger refuses any other initial status |
| `UPLOADING` → `VERIFYING`, `AVAILABLE`, `REJECTED`, `FAILED` | yes | leaving the upload requires complete content (type, size, checksum) except to `REJECTED` / `FAILED` |
| `VERIFYING` → `AVAILABLE`, `REJECTED` | yes | the scanner hook (F19); no scanner exists |
| `AVAILABLE` → `DELETING` | yes | logical deletion (17.7) |
| `DELETING` → `DELETED` | yes | after the storage delete (17.7) |
| anything else | refused | `REJECTED`, `FAILED`, `DELETED` are final in **every** field |

Stamps agree with the status (`availableAt` iff reached `AVAILABLE`; `deletionRequestedAt` iff `DELETING` / `DELETED`; `deletedAt`
iff `DELETED`; `failureCode` iff `REJECTED` / `FAILED`) and are ordered. **Temporary vs attached (SDD §5.2):** a file has a deadline
or is attached (a service's own generated file may be created attached); `attachedAt` is set once; a `DELETING` file cannot be
attached. **Immutability (ADR-0048 §3):** identity, placement and declaration columns are immutable (the kit's `forbid_column_change`);
content metadata and stamps are set once (`file_set_once`), so the same `fileId` always means the same bytes; there is no version
column and no replace operation. **Logical deletion (F17):** a trigger refuses `DELETE` on `file` for everyone, so the tombstone stays.

The transitions themselves are **not** repository operations yet: each needs its storage side (completion in 17.5, deletion in 17.7)
and will be a named conditional `UPDATE … WHERE status = …`, never a generic update. The schema already enforces them.

## 5. Ticket model (SDD §11.1, F35 / F36)

- **Digest:** SHA-256 of the token string exactly as presented (the token is 32 random bytes in unpadded base64url, 43 characters;
  generation is 17.5 / 17.6), lowercase hex. `ticketDigest(token)` checks the token shape first (anything else is `undefined`: no
  database read). The repository API takes a branded `TicketDigest` and re-checks `^[0-9a-f]{64}$` at runtime; the schema checks it
  too, so a raw token (43 base64url characters) can never be stored. Unique, indexed. No key, no encryption, no signing (F35).
- **Operations:** only `download` and `upload`. No ticket for delete, metadata, listing, administration or issuing tickets.
- **Download binding:** exactly one `fileId` at insert, plus the disposition. `recordDownload` inserts **from** the file row matched by
  id + owner + organization in one statement (`INSERT … SELECT … FROM file WHERE …`): no file of the issuer in that organization, no
  ticket, and the same `undefined` as a missing file.
- **Upload intent:** organization, `maxBytes` (1..100 MiB), `mediaTypes` (non-empty subset of the allow-list), `attach`; always
  single-use; no file at insert; the created file is recorded once (17.5).
- **Owner and organization binding:** a trigger checks, whenever `fileId` is written, that the file's owner is `issuedBy` and its
  organization **is not distinct from** the ticket's (NULL = NULL for platform files). A plain composite foreign key cannot express
  this with a nullable organization; both sides are immutable, so the check at write time holds forever. So "ticket of organization A
  → file of organization B" cannot be represented at all.
- **Expiry:** absolute `expiresAt` = database `now()` + lifetime, bounded 60..300 s by a CHECK relative to `createdAt` and immutable
  (never extended). Validity is `expiresAt > now()` on the database clock. Expired rows stay until the retention sweep (17.7).
- **Use:** `useCount` (every use) and `usedAt` (the first). Single-use means at most one use (CHECK). A trigger lets uses grow only one
  at a time and only while the ticket is not revoked and not expired: even a buggy redemption cannot use a dead ticket.
- **Revocation:** `revokedAt`, set once.

## 6. Repository layer and tenant isolation

| Operation | Scope | Returns |
|---|---|---|
| `FileRepository.createUploading(NewUpload, q?)` | owner from `FileScope` | the row; `FilePersistenceError('idempotency_key_in_use')` on a live duplicate key |
| `FileRepository.findOwned(scope, id, q?)` | owner **and** organization | the row, or `undefined` for missing / other owner / other organization / not a UUID alike |
| `TicketRepository.recordDownload(input, q?)` | issuer and organization, matched on the file in the same statement | the row (without the digest), or `undefined` |
| `TicketRepository.recordUpload(input, q?)` | issuer and organization | the row; `FilePersistenceError('ticket_digest_collision')` |
| `TicketRepository.claimUse(digest, q?)` | the digest | the claimed row, or `undefined` for unknown / expired / revoked / used up alike |
| `TicketRepository.revoke(issuer, ticketId, q?)` | issuer | `true` (idempotent) or `false` (unknown or another issuer's, alike) |
| `TicketRepository.revokeAllForFile(q, fileId)` | the caller's transaction | the count |

- **No unscoped lookup exists** (`findAnyFileById` does not exist). A redemption reads its file with `findOwned` and the ticket's own
  bindings (`issuedBy`, `organizationId`, `fileId`), so even the ticket path goes through the scoped read.
- **Non-disclosure (SDD §11, §11.1):** every "not yours / not there / not valid" outcome is one indistinguishable value, ready to be
  one `404 file_not_found` or one `ticket_invalid`. The internal distinctions (expired, revoked, used) stay queryable in the database
  for metrics, never through the repository result.
- **No generic update:** no `updateFile(id, patch)`; returned ticket rows never carry `tokenDigest`.
- **Errors:** raw PostgreSQL errors propagate to the kit filter, which answers the opaque 500 and logs the error message only.
  PostgreSQL's `detail` (which holds the failing row: a name, a storage key) is never logged; tested through a test-only probe route.
  Expected conflicts are typed (`FilePersistenceError`, a code only) for the API stages to translate.

## 7. Invariants: where each is enforced

| Invariant | Database | Application |
|---|---|---|
| owner / organization of a file and a ticket immutable | trigger | — |
| content (type, size, checksum) set once; same id = same bytes | trigger + CHECK | — |
| state machine, terminal finality, stamps agree | triggers + CHECK | — |
| no hard delete of a file | trigger | — |
| storage key shape, contains its own id, unique | CHECK + UNIQUE | generator (`newStorageKey`) |
| ticket names a file of its issuer in its organization | trigger | `recordDownload` scopes in the same statement |
| ticket lifetime 60–300 s, never extended | CHECK + trigger | `checkLifetime` |
| digest only, unique | CHECK + UNIQUE | branded type + `assertTicketDigest` |
| single use; no use after revocation / expiry | CHECK + trigger | `claimUse` conditions (atomic) |
| owner / organization on every read | — | `findOwned` (no unscoped read exists) |
| created-file limits of an upload ticket (size ≤ `maxBytes`, type ∈ `mediaTypes`) | — | 17.5 (the stream is where they are known) |
| `inline` only for images; download only of `AVAILABLE` files; issuer still holds `issue_ticket` | — | 17.6 (policy and file status at redemption) |
| organization within the caller's policy mode | — | 17.5 / 17.6 (the caller policy, 17.2) |

## 8. Transactions and concurrency

- **Single-use claim:** one conditional statement,
  `UPDATE file_access_ticket SET "useCount" = "useCount" + 1, "usedAt" = COALESCE("usedAt", now()) WHERE "tokenDigest" = $1 AND
  "revokedAt" IS NULL AND "expiresAt" > now() AND (NOT "singleUse" OR "useCount" = 0) RETURNING …`. Under READ COMMITTED, a second
  claimer blocks on the row lock and PostgreSQL re-evaluates the condition after the first commits: exactly one wins. Tested with 20
  concurrent claims through the pool, with an explicit held lock (the waiter loses after a commit, wins after a rollback), and against a
  concurrent revocation. The schema is a second barrier: a read-then-write claim (mutation M8) hits the single-use CHECK.
- **Logical delete + revocation (17.7):** `revokeAllForFile` takes the caller's transaction on purpose; the deletion will run
  `UPDATE file SET status = 'DELETING' … WHERE id = … AND status = 'AVAILABLE'` and the revocation in one `db.tx` (tested: a rollback
  keeps the tickets live, a commit revokes them, another file's tickets untouched). A redemption also re-checks the file status, so a
  ticket racing a delete can at worst start a stream just before the delete commits (the accepted residual, 17.1 threat model).
- **Idempotency:** a live duplicate `(ownerService, Idempotency-Key)` is refused by a partial unique index (no read-then-insert race);
  a `FAILED` / `REJECTED` attempt leaves the index, which permits the SDD §10 retry.
- **Creation:** one `INSERT`; the caller may pass its transaction (a test proves a rolled-back creation leaves nothing).

## 10. Migration and least privilege

`0001_file_schema.sql`, forward-only, applied after the kit baseline by the migrator (`npm run migrate`), tracked by the kit runner
(a re-run applies nothing). Readiness is 503 `["migrations"]` while it is pending **even with the kit baseline applied**, 200 after.
The runtime role `file_app` (DML through default privileges) can use the repositories but cannot: `ALTER` / `DROP` anything, disable or
drop a trigger, drop a constraint or index, replace a trigger function, `TRUNCATE`, set `session_replication_role` (all SQLSTATE 42501),
or hard-delete a file (the trigger). Verified in tests with self-provisioned roles and in the production image.

## 12. Defects found and fixed

- **The generic-service guard was blind to identifiers** (`scripts/lib/checks.mjs`): `\bstudent\b` never matches `student_documents`,
  `instructorId`, `driverPhoto` or plurals, exactly the shapes a schema or a DTO uses; and SQL migrations were not scanned at all. Fixed
  locally and backward-compatibly: identifiers are split into words (camelCase, `_`) before matching, plurals match, and the new-Core
  services' `db/migrations/*.sql` are scanned. No existing file is flagged; `test:repo` gained the cases.
- **Stage 17.1 threat-model wording** ("stored as HMAC") contradicted F35: corrected (§1).
