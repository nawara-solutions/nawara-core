# Architecture documents

Whole-system documents for Nawara Core. They are **living** (updated as the architecture evolves); the decisions behind them are
recorded as ADRs in [`../adr/`](../adr). `docs/README.md` is shared with other repositories through a symlink, so this folder is
indexed here instead.

| [`stage-10/member-membership-invariant-owner-decision.md`](./stage-10/member-membership-invariant-owner-decision.md) | Owner-decision record: **ACCEPTED AND IMPLEMENTED** (2026-09-20) — the `member`-branch `OrganizationMembership` invariant is now `[0..N]` (was `[1..N]`), migration `0009_member_zero_membership.sql`; security analysis and e2e tests confirm zero memberships grant zero organization authority; no Flow registration endpoint exists yet — only the underlying Auth capability |
| [`stage-10/flow-consumer-and-organization-participation-study.md`](./stage-10/flow-consumer-and-organization-participation-study.md) | Study: most of "Flow consumer" (browse/favorite/order/purchase, any `FlowConsumer`-shaped entity) belongs outside this repository entirely, in Flow's own future backend — the same CLAUDE.md rule and `nawara-drive` precedent that already keeps Driver's domain state out of Core; Core supplies only identity (`OrganizationMembership[0..N]`, accepted) and entitlement facts (billing's `user_subscription`/`organization_license`, ADR-0038, described in this study as unbuilt — **since built differently, as a single organization-scoped `subscription` table with no per-user dimension; see [ADR-0044](../adr/0044-subscription-entitlement-final-model.md)**); organization participation confirmed as Organization-row-under-Flow-Platform + billing entitlement, no new Core concept |
| [`stage-10/core-vs-flow-ownership-boundary-study.md`](./stage-10/core-vs-flow-ownership-boundary-study.md) | Study: applies a literal genericity test ("could an unrelated product use this without Flow-specific semantics?") to a ~20-concept ownership matrix, confirming and sharpening the prior study; its one new finding is that "organization participates in Flow" is a composite of three real, differently-owned facts (exists / commercial license / operationally discoverable) rather than one, and that ADR-0038's entitlement-status already *is* the "entitlement" layer (ADR-0044 gives its final, built shape) — no fourth Core owner is warranted; includes the recommended Core/Flow architecture diagram |
